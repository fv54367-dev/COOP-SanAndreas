## Lecciones
- Trampas generales (CRLF, asm, SB4, offsets de `main.scm`, minúsculas en nombres de script, `GetAsyncKeyState`, `FailCurrentMission`...): ver AGENTS.md > Trampas.
- **Eventos de plugin-sdk antes de `CCore::Init`:** el primer `+=` instala el gancho; si después un `RedirectCall` pisa la misma dirección (`PatchSCM` 0x748CFB), el evento no corre nunca (pasó con `initGameEvent`: nadie se conectaba). Registrarlo solo después de `CCore::Init`.
- Un guardado con `$onmission = 1` y sin el script `PSAVE1` esperando deja al jugador "en misión" para siempre. El progreso de historia es **por jugador**; la misión que arranca en coop la elige el contador del host.
- **Depurar scripts desde afuera:** variables locales de misión = `LocalVariablesForCurrentMission` (0xA48960, `n@` = índice n); scripts activos desde `CTheScripts::pActiveScripts` (0xA8B42C; nombre +8, IP +0x14, base +0x10). Muestrear cada 20 ms con `ReadProcessMemory`. En `.dmp`: Memory64List, `ScriptParams` (0xA43C78), pool de peds (0xB74490; bit 0x80 = libre).
- `PROBAR_SOLO` tiene un solo CJ de cinemática por proceso (objeto CSPLAY, modelo 1) y el ped local oculto; modelos 0 y 1 comparten el TXD `player`.
- Entidades remotas que "no se ven pero chocan": comparar `m_nAreaCode` con el del jugador local (el estadio de carreras es el 7).
- Un script de misión puede mandar su estado por `MINIGAME_VS_SCORE` con un `gameId` propio (200 = progreso de carrera) leyendo sus variables, sin tocar el script.
